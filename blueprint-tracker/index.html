✅ Task 1 — Provision the Perplexity Sonar API key (15 min)

This task gives Mariam AI its brain.

  2. Sign in with the Everest Capital Google Workspace account (so billing is on the business card).
  3. Click "API Settings" in the left rail.
  4. Click "Generate New API Key". Name it mariam-ai-prod. Copy the pplx-... value into your password manager immediately — Perplexity only shows it once.
  5. On the same page, click "Add Payment Method" and load $50 of credits. Sonar is $1 per million input tokens + $1 per million output tokens; $50 covers roughly 25,000 reader questions. Auto-recharge off for now — you want to watch the burn rate the first week.
  6. Open vercel.com/everestcapital8-gmailcoms-projects/blueprint-tracker/settings/environment-variables.
  7. Click "Add Environment Variable":
    - Key: PERPLEXITY_API_KEY
    - Value: the pplx-... value from step 4 (paste exactly, no spaces, no quotes)
    - Environments: Production + Preview + Development (all three)
    - Click Save.
  8. Stay on the project page → Deployments tab → click the ⋯ on the most recent production deployment → Redeploy → uncheck "Use existing build cache" → Redeploy. (Vercel needs to rebuild to pick up the new env var.)

✅ Task 2 — Deploy the Cloudflare Worker proxy (15 min)

This task makes sure Perplexity never sees who's asking — only what's being asked. The Worker is the brand layer, the rate-limit layer, the logging layer, and the lead-scoring layer. Reader sees Mariam AI; Perplexity sees an anonymous request from a Cloudflare IP.

  1. Open dash.cloudflare.com → sign in with the Everest Cloudflare account.
  2. Left rail → Workers & Pages → Create → Hello World template → name it mariam-ai-proxy → Deploy (you'll replace the default code in step 5).
  3. After deploy, click the new Worker → Settings → Variables and Secrets → Add variable:
    - Type: Secret
    - Variable name: PERPLEXITY_API_KEY
    - Value: the same pplx-... from Task 1, step 4
    - Save
  4. Add three more secrets the same way: SUPABASE_URL, SUPABASE_SERVICE_KEY (the long eyJ... service role key — grab it from supabase.com/dashboard/project/mocerqjnksmhcjzxrewo/settings/api), and EVEREST_LEAD_WEBHOOK_URL (the lead-routing endpoint — for now use https://example.com/placeholder and update later).

Troubleshooting

  • Calculator notice still amber after both redeploys. Hard-refresh the page (Cmd+Shift+R / Ctrl+Shift+F5). The env var is cached client-side for 5 minutes.
  • "401 Unauthorized" in browser console. The PERPLEXITY_API_KEY value got pasted with a leading or trailing space. Re-paste in Vercel, redeploy.
  • Worker returns 500 on first request. Check Cloudflare → Workers → mariam-ai-proxy → Logs → Live tail. Most common cause: the SUPABASE_SERVICE_KEY is the anon key (starts with eyJhbGc... and you can read it from a browser). It must be the service role key. Different key, same Supabase project.

🧮 Mariam's Underwriting Calculator

A live underwriting widget for room-rental properties. Punch in an address, price, bedroom count, and per-room rent — get base-case cap rate plus two stress scenarios in under a second. No login. No spreadsheet. No "request a demo."

This is the template for every calculator that will ship inside the book and the community. It's also the first surface where Mariam AI's Perplexity layer plugs in: today the calculator uses static defaults; once Phase 1 is complete, the same widget pulls current per-room comps and current OpEx ratios from Perplexity Sonar with citations to local sources.

Try it now

The math, in plain English: Gross annual rent = bedrooms × rent_per_room × 12. Operating expenses default to 45% of gross (a conservative national average for single-family room rentals — taxes, insurance, maintenance, vacancy, turnover, utilities, management). NOI = gross − OpEx. Cap rate = NOI ÷ purchase price.

Downside scenario assumes a 15% rent haircut (market softening, one room chronically below target). Stress scenario assumes a 25% rent haircut plus a 90-day full-property vacancy (worst plausible year — a major hurricane, a problem tenant working through eviction, a refi pause). If your stress cap rate is still positive after debt service, the deal is sturdy.

Reader sees Mariam-branded results; Perplexity sees only the question text. The Cloudflare Worker strips identity before any LLM call.

Building YOUR calculators (the pattern)

Once Phase 1 is live, you can ship more calculators following this same pattern without any new infrastructure:

Calculator Inputs Perplexity adds

Each one is the same architecture: HTML form + JS math + a single Sonar API call + branded output. Total build time per calculator with Claude Code dispatch: 2–4 hours.

Why this is a moat, not a feature

A book with companion calculators that pull current market data is fundamentally different from a book that doesn't. Specifically:

Static books age. This one doesn't. When Florida changes its rooming-house statute in 2027, your reader's calculator quietly starts citing the new law the next time they open it. When the per-room rent in Brevard rises 12% in a year, your underwriting calculator flags their stale assumptions automatically. The reader never sees you update anything; the book just keeps being right.

That's the white-label Perplexity infrastructure paying for itself, every day, on every reader's screen.

Hi Mariam! This guide gets you set up with GitHub so you can collaborate with Ariel on the Room Rental Double Cash Flow book without losing changes, fighting with file versions, or emailing Word docs back and forth. By the end you'll have:

Time needed: About 45 minutes for setup. After that, it becomes faster than email.

Why GitHub for a book? Authors use GitHub the same way coders do — it tracks every change, lets two people work on the same file without overwriting each other, keeps every draft you ever wrote, and runs automated audits on your manuscript. Think of it as Google Docs with a memory that goes back forever, plus an AI editor that comments on every revision.

Step 10 — When the AI reviewer comments on your draft

Every time you push a chapter edit, an AI editor automatically reads the chapter and posts a review on the Pull Requests tab. It looks for:

  • Claims that need a citation
  • Fair-housing language risk (important for a real-estate book)
  • Voice consistency with the framework-driven style
  • Reader value — would a first-time room-rental investor close the chapter knowing what to do next?

You'll get an email when a review posts. Read it. Accept what's useful, ignore what isn't. The AI doesn't have final say — you do.

Common worries, answered

"What if I break something?" You can't. Every change is recorded; Ariel or you can roll back any commit in under a minute. The whole point of GitHub is that nothing is ever truly lost.

"What if Ariel and I edit the same paragraph at the same time?" GitHub will detect the conflict and ask you to pick which version to keep. It will never silently overwrite either of you.

"What if I commit something embarrassing?" Edit it, commit the fix, push. The old version stays in history but the latest version is what everyone reads.

"What if I want to try a wild rewrite without scaring Ariel?" Make a branch: in GitHub Desktop, click the branch dropdown → New Branch → name it mariam-experimental-rewrite-ch4. Edit, commit, push as normal. Ariel never sees it on main until you decide to merge. Click Create Pull Request in GitHub Desktop when you're ready to share it.

"What if I just want to write without thinking about GitHub?" Use Typora or iA Writer for hours, commit at the end of your writing session. GitHub doesn't need to interrupt the writing flow.

🔮 Mariam AI — The Infrastructure

Perplexity is not a research tool Mariam uses. It's the LLM brain invisibly powering everything Mariam ships — her books, her websites, her community. Members talk to "Mariam AI." They never see "Perplexity."

This tab is the strategic frame and the member-facing experience. The technical architecture, multi-tenant design, and behavior-tracking schema live in the Infrastructure tab.

The thesis in one paragraph

Mariam's brand is the front door. Every reader of Room Rental Double Cash Flow, every visitor to her companion websites, every paying community member experiences a single coherent AI guide: Mariam AI. Under the hood, that guide is powered by Perplexity Sonar API for grounded, cited research; Supabase for member identity and behavior tracking; and a Cloudflare Worker layer that brands every interaction as Mariam's. Perplexity sees API calls. Members see Mariam. The branding, the citations, the personality, the offers — all Mariam. The LLM intelligence — Perplexity.

What "white-label" actually means here

Perplexity does not sell a packaged white-label product. Enterprise Pro and Enterprise Max keep Perplexity branding visible to the end user. There is no admin panel where you upload a logo and remove the wordmark.

True white-label = Sonar API + your own UI. We control everything the member sees. Perplexity provides the LLM intelligence behind the scenes; we provide the brand, the routing, the UX, the tracking. That's the build.

This is actually better than a packaged white-label product would be — we own the data layer, the analytics, and the offer surface entirely. Perplexity gets paid per token; we keep the customer relationship.

The three surfaces today

1. The Book — Room Rental Double Cash Flow

The companion hub (this site) is the first surface. Mariam AI lives here as the "Ask Mariam" experience. Members ask questions; the system grounds answers in the manuscript first, supplements with live web data via Sonar, and renders Mariam's voice and citations. Every interaction logs to Supabase.

2. The Websites

Beyond this hub, Mariam's growing web presence (current and planned) — landing pages, lead magnets, course pages, future book microsites — all run on the same infrastructure. Each website is a "tenant" in the Mariam AI platform: different theme, different knowledge base, same backend.

3. The Community

Paying members get the deepest version of Mariam AI — multi-turn conversations, persistent context across sessions, member-specific recommendations, priority response queues. The community tier is where behavior tracking matures into personalized guidance (e.g., "I see you've asked three questions about Brevard County zoning — here's the next chapter you should read, and here's a property in your search range").

What members experience

Members never type the word "Perplexity." They see:

"Ask Mariam" — a chat surface branded with Mariam's name, photo, color palette, and voice. They type a question. They get an answer in Mariam's tone, with citations to either the book or vetted external sources (filtered by us, not chosen by them).

When they ask something the book covers, the answer leads with manuscript content and a "Read more in Chapter [X]" link. When they ask something the book doesn't cover (current market data, fresh statute interpretations, news), the answer pulls live web data via Sonar and cites publicly verifiable sources.

When the member tries to ask something off-topic ("write me a haiku about ducks"), Mariam AI politely redirects: "I'm focused on rental investing. Let's keep going there."

This is scoped, branded, citation-first AI — the opposite of a generic ChatGPT clone with a logo swap.

Member behavior tracking — what gets captured

Every interaction across every Mariam AI surface logs to a single Supabase analytics layer. Examples of captured signals:

  • Identity: Email (after opt-in), first session, source attribution (which book/website/ad they came from)
  • Engagement: Pages viewed, chapters opened, time spent, scroll depth
  • Queries: Every "Ask Mariam" question + response + citations + which source dominated (book vs. web)
  • Progress: Chapter status changes in the tracker (already in localStorage; gets mirrored to Supabase once they sign in)
  • Intent signals: Specific Florida counties mentioned, dollar amounts referenced, property types of interest, recurring topics across sessions
  • Conversion events: Newsletter signup, course inquiry, "talk to a broker" request, BidDeed.AI / ZoneWise.AI hand-off

These signals feed a member funnel score that classifies each contact: anonymous reader → identified member → engaged member → high-intent lead → buyer. The funnel score is computed nightly and surfaces in Mariam's analytics dashboard with the top-scoring contacts highlighted for outreach.

How this monetizes

Three connected revenue paths, all fed by the same Mariam AI infrastructure:

Path 1 — Book + course sales. Members who engage deeply with the book hub get a soft offer to the paid course at the right moment (after they've completed 5+ chapters with high quiz scores, or after asking a specific high-intent question). Conversion data feeds back into Sonar prompts for that member.

Path 2 — Community subscription. A monthly community tier gives members ongoing access to Mariam AI, weekly group sessions with Mariam herself, and personalized chapter recommendations. The AI does the personalization automatically; Mariam shows up for the high-touch moments.

Path 3 — Vertical lead hand-off to Everest Capital. High-intent leads (members asking about specific Florida counties, foreclosure mechanics, zoning specifics) get routed via webhook to BidDeed.AI or ZoneWise.AI. The book's community becomes a paid lead-gen channel for the broader Everest Capital ecosystem — the highest-margin path because the leads are pre-qualified by their own queries.

This is why the infrastructure matters: the book by itself is a book. The book + Mariam AI + Supabase tracking + Everest hand-off is a lead generation and qualification engine that throws off three revenue streams simultaneously, all branded as Mariam's.

Supabase schema

Five core tables, each scoped to a tenant_id so the same infrastructure powers multiple properties.

-- Tenants: each Mariam property (book, website, course)
create table tenants (
  id text primary key,                  -- 'rrdcf-book', 'community', 'course-flagship'
  name text not null,
  theme jsonb not null,                 -- { primary, accent, font, logo_url }
  knowledge_base_url text,              -- where the manuscript or content lives
  sonar_system_prompt text not null,    -- per-tenant grounding prompt
  created_at timestamptz default now()
);

-- Members: identified people across surfaces
create table members (
  id uuid primary key default gen_random_uuid(),
  email text unique,                    -- nullable for anonymous-first sessions
  source text,                          -- 'book-hub', 'fb-ad-q2', 'course-landing'
  utm jsonb,                            -- full UTM capture
  tier text default 'free',             -- 'free' | 'email' | 'paid'
  created_at timestamptz default now(),
  last_seen_at timestamptz
);

-- Sessions: one per browser visit
create table sessions (
  id uuid primary key default gen_random_uuid(),
  member_id uuid references members(id),
  tenant_id text references tenants(id),
  started_at timestamptz default now(),
  user_agent text,
  country text,                         -- from CF-IPCountry header
  referrer text
);

-- Events: page views, chapter opens, link clicks, conversions
create table events (
  id bigserial primary key,
  session_id uuid references sessions(id),
  ts timestamptz default now(),
  event_type text not null,             -- 'page_view', 'chapter_open', 'cta_click', etc.
  properties jsonb
);
create index events_session_ts on events(session_id, ts desc);

-- Queries: every "Ask Mariam" interaction
create table queries (
  id bigserial primary key,
  session_id uuid references sessions(id),
  member_id uuid references members(id),
  tenant_id text references tenants(id),
  ts timestamptz default now(),
  prompt text not null,
  response text not null,
  citations jsonb,                      -- array of {url, title, snippet}
  source_dominant text,                 -- 'manuscript' | 'web' | 'mixed'
  tokens_in int,
  tokens_out int,
  cost_usd numeric(10,6),
  signals jsonb                         -- extracted: counties, dollar amounts, topics
);
create index queries_member_ts on queries(member_id, ts desc);

-- Funnel scoring (recomputed nightly)
create table funnel_scores (
  member_id uuid primary key references members(id),
  score int not null,                   -- 0-100
  stage text not null,                  -- 'anonymous' | 'identified' | 'engaged' | 'high_intent' | 'buyer'
  signals text[],                       -- ['asked_about_brevard', 'mentioned_500k', 'viewed_ch_U_3x']
  next_best_action text,                -- 'send_course_offer' | 'route_to_biddeed' | etc.
  updated_at timestamptz default now()
);

Row-level security keeps members' data isolated per tenant. Mariam (and Ariel, as admin) see aggregate analytics across all tenants in the dashboard.

The Cloudflare Worker (proxy + brand layer)

// worker.ts — Mariam AI proxy
import { createClient } from "@supabase/supabase-js";

interface Env {
  PERPLEXITY_API_KEY: string;
  SUPABASE_URL: string;
  SUPABASE_SERVICE_KEY: string;
}

export default {
  async fetch(req: Request, env: Env): Promise<Response> {
    const url = new URL(req.url);
    if (url.pathname !== "/api/ask") return new Response("Not found", { status: 404 });

    const { tenant_id, session_id, member_id, question } = await req.json();
    const supa = createClient(env.SUPABASE_URL, env.SUPABASE_SERVICE_KEY);

    // 1. Load tenant config
    const { data: tenant } = await supa.from("tenants").select("*").eq("id", tenant_id).single();
    if (!tenant) return new Response("Unknown tenant", { status: 400 });

    // 2. Check rate limit / tier
    const member = member_id
      ? (await supa.from("members").select("*").eq("id", member_id).single()).data
      : null;
    if (!isWithinTierLimit(member, supa)) {
      return Response.json({ error: "tier_limit", upgrade_url: "/community" }, { status: 429 });
    }

    // 3. Call Sonar with tenant-specific system prompt
    const sonarRes = await fetch("https://api.perplexity.ai/chat/completions", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${env.PERPLEXITY_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        model: "sonar-pro",
        messages: [
          { role: "system", content: tenant.sonar_system_prompt },
          { role: "user", content: question },
        ],
        return_citations: true,
        search_domain_filter: tenant.allowed_domains ?? undefined,
      }),
    });
    const sonarData = await sonarRes.json();
    const answer = sonarData.choices[0].message.content;
    const citations = sonarData.citations ?? [];

    // 4. Post-process: brand tone, citation formatting, off-topic redirect
    const branded = applyMariamVoice(answer, tenant.theme);

    // 5. Extract signals (counties, dollar amounts, topics) for funnel scoring
    const signals = extractSignals(question, answer);

    // 6. Log to Supabase
    await supa.from("queries").insert({
      session_id, member_id, tenant_id,
      prompt: question, response: branded,
      citations, source_dominant: classifySource(citations, tenant),
      tokens_in: sonarData.usage.prompt_tokens,
      tokens_out: sonarData.usage.completion_tokens,
      cost_usd: computeCost(sonarData.usage, "sonar-pro"),
      signals,
    });

    // 7. Trigger Everest hand-off if signals indicate high intent
    if (signals.high_intent_lead) {
      await queueEverestWebhook(member_id, signals);
    }

    return Response.json({ answer: branded, citations });
  },
};

Key design choices:
- Tenant config in DB, not code. Adding a new website = insert a row in tenants, no redeploy.
- System prompt per tenant. The Mariam-AI voice on the book hub vs. on the community site can diverge intentionally.
- Search domain filter. Sonar can be constrained to vetted sources (Florida government sites, BLS, Census, peer-reviewed) — a critical guardrail for a citation-first product.
- Cost computed per query. Every query has a cost_usd column. The dashboard shows cost per member, cost per tenant, cost per question category. No surprises.
- Signals extracted at log time. Funnel scoring runs nightly off these signals, not real-time.

Style Guide — Room Rental Double Cash Flow

Short rules. Each rule earns its place because breaking it makes
the book worse for the reader.

Voice

  1. Direct. No "it depends" without a follow-up framework for
    deciding. If the answer truly depends, name the variable it
    depends on and give the reader a way to figure out which side
    they're on.

  2. Concrete. Real numbers, real properties, real moments.
    Generic abstractions are the enemy. "A property" loses; "a
    7-bedroom 1948 Cape Cod off Main Street that we bought for
    $342K" wins.

  3. Frameworks over feelings. Every chapter delivers a named,
    memorable framework. If a reader three years from now can't
    summon the framework's name when standing at a property, the
    framework failed.

  4. No hedging. "May," "might," "could potentially" are usually
    fear masquerading as nuance. Either say it or don't.

  5. The reader is the hero, not the author. Mariam's expertise
    is the lens, not the subject. The reader's situation, decisions,
    and outcomes are the subject.

Structure

  1. Cold open earns the first 50 words. No "Welcome to Chapter
    4." No "In this chapter we'll discuss..." Open with a moment, a
    question, or a sharp observation that makes the reader want
    paragraph two.

  2. Every chapter delivers one deliverable. Named in the front
    matter. Named in the opening. Named in the closing. If a
    chapter has two deliverables, it's two chapters.

  3. Transitions earn their keep. The last paragraph of each
    chapter should make the reader want to start the next one.

Citations and accuracy

  1. Florida-specific claims need a citation. Statute number,
    code section, or municipal ordinance. Citations live in
    audit/citations.md. The audit workflow flags uncited claims.

  2. Fair housing is non-negotiable. Every framework uses
    lawful proxies (work pattern, price tolerance, commute,
    employment density, wage band). Never protected class. Never
    a wink toward protected class. Never a "you know what I mean"
    about a neighborhood.

  3. Numbers are exact or named as estimates. "$3,200/mo" is a
    claim; "around $3K/mo" is an estimate. Don't mix them. If
    it's an estimate, say it's an estimate and explain the range.

Formatting

  1. One H1 per chapter (the chapter title). Use H2 for major
    sections, H3 for subsections. No H4+ in this book.

  2. Bullet lists are for parallel items only. If three things
    being listed aren't structurally parallel (same grammar, same
    category), use prose.

  3. Code-block monospace is for templates, formulas, file
    names, and direct commands.     Not for emphasis. Emphasis is
    **bold** (rare) or *italic* (rarer).

  4. Pull quotes use the > block-quote syntax. Reserve them
    for one or two sentences per chapter that you want the reader
    to underline.

What we don't do

  • We don't use exclamation points outside of dialogue.
  • We don't use emoji in chapter body text. (Companion icons in
    front matter are fine; they're rendered separately by the
    tracker, not in the book.)
  • We don't address the reader as "buddy," "friend," "rockstar,"
    or any other artificial warmth marker. Just "you."
  • We don't apologize for the book's directness. Readers chose
    this book; they want direct.

A reminder

A book is a gift to the reader's future self. Every sentence is
optional from the reader's perspective. Earn the next one.
